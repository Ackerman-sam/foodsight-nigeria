# FoodSight Nigeria — Dashboard

Phase 5 / Objective 4 deliverable: a Streamlit dashboard with five views (Overview, Forecast,
Drivers, Price Status, Methodology) for the nine core NBS food commodities. Built for desktop
and revised through two senior UX review rounds.

## Views

| View | What it shows |
|---|---|
| **Overview** | Four KPI cards (current price, 6-month outlook, price status, forecast accuracy), a one-paragraph plain-language insight, the price history + 6-month forecast chart, top three drivers, and the current status. A note appears when the latest observation is two or more months old. |
| **Forecast** | Full forecast chart with range (2Y / 3Y / 5Y / All), optional event markers (COVID-19, subsidy removal) and status thresholds, plus the monthly forecast table with 80% bounds. |
| **Drivers** | SHAP-based driver shares (LightGBM) in plain language, and a waterfall explaining next month's LightGBM estimate (interpretation only). |
| **Price Status** | Normal / Watch / High for today and for next month's forecast, distance to thresholds, the threshold chart, and a month-by-month back-test of the alert (Jan 2023 – May 2026) with a summary for all commodities. |
| **Methodology** | Selected model and accuracy (MAPE, MAE, MSE, RMSE), the naive last-value benchmark, accuracy before vs after the subsidy removal, the structural-break analysis, thresholds, data sources, and a "Data files in use" panel. |

Navigation is a sidebar: **Category → Commodity** selectors, then the view switcher.

## Running locally

```bash
pip install -r requirements.txt
streamlit run app.py
```

Opens at `http://localhost:8501`. No API keys or external services — everything reads static
CSVs in `data/`.

## Deploying to Streamlit Cloud

1. Push the folder (`app.py`, `requirements.txt`, `.streamlit/`, `assets/`, `data/`) to GitHub.
2. On [share.streamlit.io](https://share.streamlit.io), point a new app at the repo, main file `app.py`.
3. No secrets or environment variables needed.
4. After changing `.streamlit/config.toml`, reboot the app from the Streamlit Cloud menu.

## Data files (in `data/`) and where each comes from

File names must match **exactly** (no `_1` or random suffixes from repeated downloads).

### Required (the app stops with an error if any is missing)

| File | Generated by | Regenerate when |
|---|---|---|
| `FoodSight_national_merged.csv` | Notebook 02 (National Merge) | Any data / cleaning change |
| `future_forecasts_6mo.csv` | Notebook 06 (ARIMA re-fit on the full series, 80% interval) | Monthly, as new data arrives |
| `all_commodities_mape_summary.csv` | Notebooks 05 / 06 | Any model / feature change |
| `all_commodities_shap_pct.csv` | Notebooks 05 / 06 | Any model / feature change |
| `alert_thresholds.csv` | Notebook 06 | Monthly |
| `structural_break_summary.csv` | Notebook 03 (EDA / Structural Breaks) | Rarely (break date is fixed) |

### Optional (a section is simply hidden until its file is added)

| File | Generated by | Unlocks |
|---|---|---|
| `all_commodities_model_comparison.csv` | Notebooks 05 / 06 | Methodology: MAE / RMSE cards, metric tabs, naive benchmark |
| `all_commodities_subperiod_metrics.csv` | Notebook 06 | Methodology: before vs after subsidy-removal table |
| `alert_backtest.csv` | Notebook 06 | Price Status: back-test chart and summary |
| `shap_local_next_month.csv`, `lgbm_next_month.csv` | Notebook 06 | Drivers: next-month waterfall |

**`all_commodities_model_comparison.csv`** is long-format (`commodity, model, MAE, [MSE,] RMSE, MAPE`).
It must contain rows for **ARIMA, ARIMAX, LightGBM and Naive**; without the Naive rows the
Methodology tabs fall back to a MAPE-only table. The `MSE` column is optional and adds an MSE tab.

**`future_forecasts_6mo.csv`** is not a by-product of the model-comparison notebooks: each
commodity's `auto_arima` order is re-fit on the *entire* series, then forecast 6 months ahead
with an 80% interval.

**`alert_thresholds.csv`** holds the rolling 24-month 75th / 90th percentile thresholds (used by
the traffic light), the pre-subsidy (before April 2023) percentiles kept for reference, and the
next-month forecast status. Thresholds are rolling because prices rose structurally after the
May 2023 subsidy removal; a fixed pre-2023 baseline would flag every commodity as High.

## Monthly refresh

1. Add the new month to the raw data and re-run Notebook 02.
2. Re-run Notebooks 05 and 06.
3. Copy the notebook-06 dashboard output folder into `data/`, commit and push.
4. The app notices replaced files automatically (its cache is keyed on file modified-times). If
   anything looks stale, open **Methodology → Data files in use** to see which files were found
   and when they were last modified, then reboot the app.

Tip: open CSVs in Excel for viewing only. Re-saving from Excel can change formatting and break loading.

## Evaluation summary (as shown in the app)

- Walk-forward, one-month-ahead, 41 test months (Jan 2023 – May 2026); ARIMA, ARIMAX and
  LightGBM are scored on the **same** window.
- ARIMA is the best of the three models for all nine commodities; it beats the naive
  last-value benchmark on 8 of 9 and ties on 1 (Maize).
- The "before subsidy removal" window contains only 4 test months, so its figures are indicative.

## Design notes / known limitations

- **Forecast horizon:** 6 months ahead, ARIMA only. Only month 1 is evaluated out of sample;
  months 2–6 and the 80% intervals are model-based and have **not** been back-tested for coverage.
- **Driver view:** SHAP values come from LightGBM even though ARIMA is more accurate; they explain
  what correlates with price movements, not the mechanism behind the ARIMA forecast. Fuel price
  and CPI are trending, collinear series, so fuel's large share plausibly stands in for the
  post-2023 price regime. The next-month waterfall holds drivers at their last observed values.
- **Price Status:** the rolling alert was Watch or High in roughly 27–38 of 41 back-tested months
  per commodity because prices rose through the period. Read it as "high relative to the last two
  years", not as an early-warning signal.
- **ARIMA orders** were selected once on the full series, which introduces mild look-ahead in the
  walk-forward evaluation (see the report's limitations).
- **Small numerical differences** (up to ~0.03 percentage points of MAPE for some ARIMA fits) can
  occur across library versions; quote the final notebook outputs.
- **National level only.** No state / zone breakdown, consistent with the project's scope decision.
- **Usability evaluation** with real non-technical users has not been conducted. The design was
  revised against two expert UX reviews, but that is not a substitute for user testing and should be
  stated as such in Chapters 4 and 5.
